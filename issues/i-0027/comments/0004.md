### What this points at

The failure is not in the IDE's fs handler. Somewhere between the agent's tool dispatch and the ACP `fs/read_text_file` call, the read is being answered by the local filesystem instead — which, inside the sandbox stub, means "exists" for the four or five instruction files and "File does not exist" for everything else in the project. The two triggers observed so far (an IDE restart, and an agent respawn after `publish --ready` removes the container under a live session) are both events that re-spawn the agent process, which fits: whatever advertises the fs capability to the agent is not being re-established on the respawn path, so the agent falls back to its own filesystem and never reports an error, because from its point of view nothing failed.
