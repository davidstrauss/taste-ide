Second trigger, observed live in i-0029 on 2026-09-16, and it is not an IDE restart: the IDE stayed up the whole time.

The sequence is in the app log:

- 01:58:54 `environment i-0029 moved along the review arc` — this environment published with `ready: true`, which stops its container.
- 01:59:00 `taste_devcontainer::channel: environment channel helper: Error: container has already been removed`
- 01:59:01 `chat i-0029: connection closed (Process exited with exit status: 255 … Error: container has already been removed)` — the agent died with the container it was living in.
- 01:59:03 `chat i-0029: spawning its agent (resume=507f8fa7-…)` — the IDE respawned it on the persisted session id.

Since that respawn, `fs/read_text_file` answers "File does not exist" for every path, in exactly the pattern this issue describes:

- `…/environments/799fd7acd369bf5c/i-0029/repo/README.md` — fails
- `…/environments/799fd7acd369bf5c/i-0029/repo/crates/taste-mcp/src/orchestration.rs` — fails (`ide_list_files` lists it, `ide_write_policy` calls it writable, `ide_exec` reaches it)
- `/var/home/straussd/Projects/taste-ide/crates/taste-mcp/src/orchestration.rs` (the primary checkout) — fails
- `…/i-0029/repo/CLAUDE.md` — *succeeds*, and only because that content was already in the session's context; a path that had not been read before never answers.

`ide_open_file` with a workspace-relative path resolved to `/var/home/straussd/Projects/taste-ide/…` from this i-0029-bound session, which is the same clue the original report names.

So the binding is lost by **any respawn of the agent process on a resumed session**, not by an IDE restart specifically — a restart is one way to get one, and `publish --ready` stopping the container under a live session is another. That second way is reachable by an agent's own normal last act, which makes it considerably easier to hit than the reported repro: every environment that publishes and is then asked to do one more thing lands here.

It also cost something concrete. i-0029 was asked to merge `main` back into its branch and resolve the conflicts; one file conflicts, the fs leg is down, and the standing house rule forbids reading project files through `ide_exec`. The environment is stopped at exactly the impasse the "Why it matters more than it looks" section predicts.
