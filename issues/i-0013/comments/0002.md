Phase two is in: the clones are bounded by space (0b57da3, on top of the running cap in c6a6321 and a merge of main at 2546d07).

The shape, for review:

- **The budget and the scope are one line apart** in `taste-core/src/environment.rs`. `MAX_ORCHESTRATED_DISK_BYTES` = 10 GiB answers "how much"; `DISK_BUDGET_SCOPE` answers "how much of what", and is an enum of `ClonesOnly` / `WholeEnvironments` with a comment on each saying which question it settles. **`ClonesOnly` stands pending David's answer** — under `WholeEnvironments` the very first `issue_start` on this repository would refuse, and a ceiling that forbids everything is indistinguishable from a bug. Changing the answer is a one-line edit, and it propagates to the walk's cost, the report, and both refusals.
- **Both entry points**: `issue_start` and the `devcontainer_reload` restart path, with the same narrowing the running cap gets there (an environment that already holds a container is not asking for more disk). Each refusal names the budget, what is held against it, the scope in words, and what to do — and the two differ where they must: the cap says wait or destroy, the budget says destroy, and says that stopping gives back the container and keeps every byte.
- **No `du` on the request path.** `EnvironmentRegistry::start_disk_meter` walks on a background cadence (the scope's own interval: 120 s pruning, 900 s walking artifacts), each supervisor caches a `DiskSample`, and the gates read `registry.disk_budget()` — a sum over caches that touches no filesystem. `issue_start` additionally spawns a measurement of the environment it has just created, so six starts inside one interval are not weighed as nothing.
- **Allocated, not apparent**: `st_blocks` × 512, because the honest number for a disk filling up is what is consumed; fuse-overlayfs passes the lower filesystem's `st_blocks` through. The existing fleet display keeps apparent size — one walk now returns both.
- **The clone/artifact split is git's own** (`GitWorkspace::ignores`, new), and an ignored directory is pruned rather than counted, which is what makes the cadence affordable at all.
- **Surfaced**: `issue_list` gained a `disk` object beside `running` and `cap` — used and budget in bytes and in words, remaining, the scope, how many environments are in the sum, how old it is, and a note when the sum is a floor. `runtime.diskBytes` is filled whenever something has walked the whole environment (the user's Refresh, or the cadence under `WholeEnvironments`); under `ClonesOnly` it stays null, because filling it *is* the 111 GiB walk this design exists to avoid.
