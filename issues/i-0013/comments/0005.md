Reviewed and **merged** as a fast-forward to `9a8cbc7`. Gate re-run here on the merged tree: fmt clean, clippy clean, and `cargo test --workspace --no-fail-fast` with **zero failures** — the inotify tests passed this time too, which is consistent with the machine-wide `fs.inotify.max_user_instances` exhaustion rather than anything in this code.

Both outstanding items are in, and the shape is right.

The floor is the third constant beside the other two, so the three ceilings are read together. `free_bytes` takes `f_bavail` rather than `f_bfree` — the space a filesystem reserves for root is not space an agent may take, and a floor counting it would clear itself on a disk nothing could be written to — and multiplies by `f_frsize` rather than `f_bsize`, which is the multiplier that is actually right and the one that goes wrong silently. The walk up `Path::ancestors()` answers the question before the environments directory exists, which is the fresh-workspace case. `free_disk()` asks about the environments' own base rather than the workspace's, which is the honest volume when the two differ. It is read on the request path, one syscall, never through the meter's cadence; and it fails open when the kernel will not answer, matching what `DiskBudget::spent()` already does on an unmeasured workspace.

The refusals are the part I care most about, since for a while they were going to be the whole user experience of this feature. Both name what is free, what the floor is, and the shortfall — and both say the way through is not destroying an environment, because destroying every clone would not give the gibibytes back. `issue_start`'s goes further and says so with the numbers: it quotes what the clones actually hold against their budget, so the reader can see it is not the budget talking. Both keep naming the user's own Start as unbounded. `issue_list`'s `disk` object now carries `free`, `floor`, `below_floor`, and `volume`, and its `note` says plainly when the floor rather than the budget is what refuses — so the state is readable before it is a surprise.

Also fixed here: a doc comment that 0b57da3 had left stranded over `disk_json` instead of `issue_with_runtime`. I missed that in the previous review; the agent caught it.

One note for the record, since the branch says so too: free disk on this machine went from 6.9 GiB to ~119 GiB while the work was underway, so the floor does not currently refuse anything. The refusal text was written as though it did, which is right — it is one stale `target/` away from being true again.

`libc = "0.2"` is new at the workspace root, declared for `statvfs` and already present transitively, so it buys the declaration rather than the build.

i-0013 is done. All three ceilings — six running environments, ten gibibytes of clones, and ten gibibytes of free disk — are enforced at both entry points, reported where an agent can read them, and documented in `docs/ENVIRONMENTS.md`.
