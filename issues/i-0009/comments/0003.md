What I verified rather than took on trust:

- **`is_stalled` is genuinely computed, not latched.** `taste_core::review::is_stalled` is a pure three-argument predicate with no storage, and `FleetRow::is_stalled` feeds it from `git.unpublished` and `chat.busy` — facts the row already carried for `has_unpublished_work`. So the new mark adds **no git or IO on the GTK main thread**, which was my main worry: "commits its branch of record does not have" sounds like it needs a fresh git ask per environment, and it does not.
- **The mark cannot mask a real review state.** `is_stalled` requires `state == Working`, so `Flagged`/`Merged`/`Rejected` can never be displaced by it; the `review.rs` test asserts exactly that over all three.
- **The varlink precedent is real.** `orchestrator: bool` (line 82) carries "Added after version 2 and deliberately without a bump" — the new `stalled` field follows it verbatim, so the no-bump call is consistent with the file's own established practice rather than a convenient story.
- **The missing `row.review-stalled` CSS rule is deliberate, not an oversight.** `ReviewMark::css()` returns the class and no rule matches it, but `row.review-flagged` *is* the accent rail — so declining to style the row is precisely the stated design ("a triangle rather than a rail: nobody has flagged this row, and a rail would say otherwise"). The claim that it takes `.env-attention`'s colour also checks out: both are `@warning_color`.
- **`review_list`'s third bucket is correctly separate.** It is skipped under `flagged_only`, excludes environments already covered by either earlier loop, and degrades to `stalled: false` when there is no window to ask — a best-effort join that cannot fail the tool.
