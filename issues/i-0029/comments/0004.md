**The design answer for the i-0028 interaction, which needs no change to `resolve_model` itself.** It is pure and resolves membership against whatever list it is handed:

```rust
resolve_model(wanted, advertised, current) -> Default | InForce | Refused { wanted, running }
```

So `private` comes out `InForce` provided `build_model_controls` calls it with the list `with_private_choice(...)` returns rather than the raw `model_choices(&config_options)` — an ordering constraint at one call site, after the augmentation and in place of the old stale check, not a change to the function.
