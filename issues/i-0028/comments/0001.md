Done and published on `agents/i-0028`, except the two items that were waiting on the spike's comment — which never arrived, so they are i-0034 rather than a guess.

**The proxy.** Two upstreams, chosen per request from the placeholder. `Route` is keyed by the environment the placeholder was minted against; since a chat *is* an environment's conversation (`ChatEntry`), "per chat" and "per environment" are one sentence here, which is why no new identity had to be invented. `Route::Anthropic` is the default, so the private server is reached because a route was set rather than because one was absent. The credential is chosen in the same `match` as the destination, so neither key can reach the other host by a branch somebody forgot. A route with nothing behind it **fails the request** — no fallback to the API, because a chat deliberately put on the user's own hardware must not quietly spend their subscription when a file goes missing.

**The setting.** `$XDG_STATE_HOME/taste-ide/private-model.json`, beside the Anthropic credential, re-read on mtime/length change exactly as that one is. `kind` names the header (`api_key` → `x-api-key`, `bearer` → `Authorization: Bearer`) and is the user's to say rather than the IDE's to sniff: `llama-server --api-key` is one flag whose accepted header has moved across releases, and trying both in turn means sending the key to a server that already refused it. `context_tokens` is optional and is the server's `-c`, so the context gauge measures the window that exists instead of assuming 200k.

**The picker value, which is the decision you asked to be written down.** The `private` row is the IDE's, and it is **never sent to the agent**: choosing it moves the route and leaves the agent's own `model` option where it was. The server serves the one model it loaded whatever name the request carries, so the name in the request is not a choice anybody is making, and telling Claude Code it is on something else would be inventing a fact to satisfy a schema. The alternative was real — `ANTHROPIC_CUSTOM_MODEL_OPTION` takes "any string your API endpoint accepts" — and was rejected because there is exactly one such row and the proxy already spends it on the account's top tier, so buying the private entry would cost the Fable entry for every user who owns a private model and most of the time is not using it. Written into `taste_authproxy::private`'s header and ENVIRONMENTS → the model-choice section, not only here.

`issue_start` needed no change: it validates against `advertised_models`, which is the same list the drop-down renders (`with_private_choice`, one function, two callers), so the row the user can pick and the value the tool accepts cannot drift apart.

**The header.** On the private route the Plan gauge is not dimmed or zeroed, it is **replaced** by the word "Private" in the same slot — there is no subscription figure to report for a conversation not drawing on one, and a gauge beside it would be the exact thing this issue says must not happen. The context gauge stays, because that one is this conversation's. The Utilization tab says the same at the head of its Subscription section, which the probe frame is what caught: "Private" in the header over an unqualified Subscription breakdown read as a contradiction.

**Two things the frames changed.** Asking `private_label.is_visible()` for the route was wrong — GTK answers for the widget *and its ancestors*, so during construction it said no to a label just shown, and the next `set_pool` put the account's gauge back beside the mark meant to replace it; the frame showed two marks in a row with room for one, and "Private" cut off at the pane's right edge. It is a `Cell<bool>` now. And the mark sits *before* the gauge it replaces rather than after, so whichever is up occupies the same place in a row that is cut from the right.

**Gate.** fmt, clippy `-D warnings`, and `cargo test --workspace` all pass, except `taste-core::watcher`, which fails on this host because `fs.inotify.max_user_instances` is 128 and the fleet shares it — a different subset each run, unchanged under `--test-threads=1`, and nowhere near this change. Filed as i-0033. Probes at 1440x900 and at the consolidated rung: `fit chat` ok at both, no near-misses on the header, and the row's own minimum *falls* from 374 to 293 on the private route, since one word replaces a word and a gauge.

Held back, and now i-0034: the count-tokens shim and any reasoning-content handling. Both need one real turn through the shipped path to answer, which is now a much smaller act than the spike was — write the file, pick the row, prompt it. No env var, no restart.
