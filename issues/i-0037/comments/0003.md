Built and committed (`f4bb3e0`, on top of `2ec85b0`). The design in the first comment is what shipped; what follows is what changed and what the gate says.

## What exists now

`taste-env-<key>-<env>-home` at `/home/agent` is unchanged in name and contents and is now only the **conversation**. `taste-id-<key>-<agent>` (`environment::agent_identity_volume`) mounts over that agent's own config directory inside it and is the **sign-in**, shared by every environment of the workspace. The table of which directory that is per agent is `policy::AGENT_IDENTITY_DIRS` — `gemini` → `.gemini`, `copilot` → `.copilot`, Claude Code deliberately absent — and `policy::agent_identity_mount` is the one place the volume and its destination are paired, so no site can hold half of it.

The five sites, as promised: `AgentClient::spawn` and `login_command` each derive this agent's pair and hand it to `sandbox::container_agent_args`; `Supervisor::ide_mounts` mounts **every** agent's, because `relocated_agent_command` carries none and cannot; `sandbox::wrap` needs nothing. `env_volumes` deliberately does **not** list them, with the reason in its doc comment: an environment mounts them and does not own them, so one environment's cleanup cannot take the fleet's sign-in and the disk budget does not bill the same bytes N times.

## Two things the design comment did not foresee

**The hosting probe had to learn about them.** `probe_agent_hosting` tested `test -w /home/agent` and repaired with one `chown -R`. That passes on every container after the first — the home was repaired long ago — while a brand-new `.gemini` under it, a separate volume podman hands to root separately, is unwritable. A sign-in would have failed for a reason nothing reported. The probe now asks about each directory by name in one exec and names the failing one on stderr.

**The sweep's volume pass is about a leak that already existed, not one this created.** As predicted, the split orphans no volume. But `sweep_legacy_resources` never looked at volumes at all, so a workspace that crossed a naming generation still holds its old homes, and `taste-agent-home` is leaked by every machine that ever ran the single-environment scheme. `legacy_volumes` finds both and `SweepReport::volumes` **reports without removing** — a container and an image are rebuildable, a home volume is somebody's conversation, so its removal is the user's, exactly as `remove_volume` already treats a live one.

The mid-turn answer shipped as decided, including the courtesy: `Chats::note_shared_sign_in` puts a meta row in every other chat of this workspace on that agent when a sign-in finishes. It was cheap after all, so it is not the part that got dropped.

## Gate

`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` all clean in this environment's devcontainer. Notably the `watcher` and `configwatch` inotify failures the prompt warned about did **not** appear in the final run — the per-user instance limit had room by then — so this is a genuinely green workspace suite rather than a green-except-those.

Tests for the gate the issue asked for: `two_environments_share_one_identity_and_no_conversation` (two homes, one identity, in one assertion pair), `the_agent_and_its_auth_terminal_mount_one_identity`, `the_ide_mounts_carry_every_agents_shared_sign_in`, `only_the_agents_that_sign_themselves_in_have_an_identity`, `an_agents_id_cannot_smuggle_anything_into_a_volume_name`, `the_legacy_volume_stem_matches_no_current_volume`, `legacy_volumes_are_this_workspaces_old_ones_and_the_global_one`, `an_orphaned_volume_is_named_and_left_alone`.

No probe run: the only visual change is a meta row in the transcript, which is existing styling and no new widget or layout.

## Not verified live, and worth saying

The nested-volume ownership path — podman creating `/home/agent/.gemini` as a fresh volume inside another volume's mount point — is reasoned from the mechanism the home volume already relies on and from the repair the probe now performs, not observed. There is no podman inside this environment's devcontainer to try it in. The first real sign-in after this ships is the measurement, and if the chown does not reach it the probe now refuses relocation and names the directory rather than failing silently.
