**The agent-home-volume half is a follow-on: i-0037, filed and linked.** Decided before touching it, as the shape bullet allows.

The reason it does not belong here: the per-environment key is load-bearing, and `env_home_volume`'s own comment says why — "with N environments it would also mean N agents writing one home concurrently". Keying the home by `(workspace, agent)` gives that concurrency straight back, so Phase 4 is not a re-key but a **split**: a shared identity volume (`~/.config/gh`, Gemini's OAuth file) mounted beside a per-environment conversation home, moved at every spawn site at once — `aim`, `relocate`, the always-outside-confined auth terminal, and the supervisor — with the orphaned volumes swept and reported. That is a design, not a rename, and it touches nothing this issue does: the Anthropic credential never enters a container at all.

**Landed so far (a68fdba), the proxy and credentials half:** `anthropic.json`, `private-model.json`, and `models.json` all move under the workspace's own state directory, keyed by the root's hash the way the state file is; resolution is aimed path → the two documented environment variables → this project's file → nothing, with no machine-wide file consulted anywhere. The model listing moved too, because it caches what *that credential's* account can run — a work account's top tier in a personal project's picker would be the same leak wearing a cache. Tests: two projects resolve two credentials and neither lends to the other, an unprovisioned third is refused naming its own path rather than served out of a neighbour's, and the private model scopes the same way without falling back to the API.

**No label means the header shows nothing** — not the file's kind. "API key" is a fact about the mechanism, not about the identity, so it would answer a question nobody asked and put a permanent caption in a row measured to the pixel. The label exists to tell two identities apart; a user with one has nothing to tell apart.
